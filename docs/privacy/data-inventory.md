# Data inventory

> **Not legal advice.** Prepared by engineers from the ADRs (ADR-0003…0030), the
> design-decision register C-01…C-112 (a later decision wins over an earlier one; C-99…C-109 record the day-0 spike results) and desk research; not
> reviewed by counsel. "Legal basis" cells are **placeholders** for counsel. Where neither an ADR nor a
> design decision settles a detail, the cell says so.

Legend — **Where it exists:** `mem` = process memory only · `spool` = the local fsync'd spool on each edge node
(deleted on acknowledgement, never older than 72 h; there are **no** copies in object storage or anywhere else, C-77)
· `umami` = Umami database (including the per-site twin websites for events without a visitor identifier, C-73) ·
`scf` = our database · `queue` = OTLP persistent queue (72-hour cap: `scfsanitize` stamps the receipt time as resource attribute `scf.received_at_unix_nano`, and the writer drops points received more than 72 h earlier, counted `undeliverable_72h` (C-112); the queue size limit stays as the second bound, C-107; the 48-hour late-data bound of the sanitise step is a data-quality rule, `too_old`; it holds the request, our `x-scf-*` metadata and the peer address — the gateway forwards no other header, C-107) · `logs` = operational logs (30 days, C-71) ·
`backup` = encrypted backups (erased or expired data leaves backups within 56 days: 35-day retention + up to 7 days until the next full + 14 days as a previous version, data-model §14; C-29, C-112). **Retention `EW`** = the event-level web window: **90 days by
default, settable 30–395 days by an `operator_admin` (395 days is the hard maximum); a tenant may choose a shorter
period per site** (ADR-0011; C-54, C-18). **Who can see:**
T = the tenant's own users (by role; dashboards apply `anonymous_reports` — rows < 10 merged into "Other", counts
rounded to 10 — unless the tenant switched it off, C-51) · S = SCF operators (thresholded, rounded aggregates only,
through `op_*` functions, C-17) · P = the public or `pub` share-key holders, only if the tenant switched public stats
on (thresholded, rounded, C-14/C-47) · O = service-operator administrators (infrastructure access) · — = nobody (not
retained). **Legal basis placeholder:** `LB-T` = tenant's basis as controller (expected Art. 6(1)(f) + the ePrivacy
route in [`jurisdictions.md`](jurisdictions.md), or consent through the consent-gated mode, C-55) · `LB-O` = service
operator's basis as controller (portal accounts, audit, security/ops; C-59) · `n/a` = not personal data.

Backups are protected by **blob versioning** instead of a no-delete credential (C-108, replacing that half of C-66):
pgBackRest cannot complete a backup without delete rights (S-08), so database nodes may delete current blobs but not
previous versions, pgBackRest's own `expire` enforces the 35-day window, and a lifecycle rule deletes previous versions
after **14 days**. Erased or expired data therefore leaves all backups within **56 days** (35-day retention + up to 7 days until the next full + 14 days as a previous version, data-model §14; C-112,
correcting C-29's 35 days). The versioning protection is untestable on the local Azurite stack (risk R-23).

## 8. Fields we explicitly never collect

- IP addresses (full or truncated) in any stored form; IP-derived region, city or coordinates.
- Raw User-Agent strings; high-entropy client hints; TLS fingerprints or any other
  fingerprint hash in any stored form (the gateway computes a JA4 fingerprint and HTTP/2 preface features per
  connection in memory only, for the `transport_mismatch` signal — never logged, stored or forwarded, C-124).
- Cookies, localStorage, sessionStorage, IndexedDB entries (except the visitor's own opt-out flag).
- Query strings, URL fragments, UTM/campaign parameters, advertising click IDs (`gclid`, `fbclid`, `msclkid`,
  `ttclid`, `li_fat_id`, `twclid`) — the gateway discards any it still receives (C-65).
- Page titles (not collected at all; there is no setting to collect them, C-89); form contents; session replay; heatmaps; scroll or mouse traces; browser error reports; web vitals.
- Umami `distinct_id`, `identify()` traits, `session_data`, `session_link`.
- Any identifier that spans sites, tenants or days.
- Stellar account keys (G/M), contract addresses of users, transaction hashes, XDR, signatures, memos, secret seeds (S…),
  balances, amounts — in web events and wallet events; in web page paths, custom events and API routes they are
  replaced by placeholders or `{redacted}` before storage (C-52, ADR-0012). **No visitor's address is ever collected.**
  The only Stellar accounts stored are the ones a project declares as its own in its Registered Footprint (and the
  sign-in accounts of tenant members, §4): the platform keeps only accounts a project proved are its own, and for at
  most 30 days the account of an open claim under verification; a rejected or removed account is deleted at the next
  hourly retention run (C-137, C-144). The only transaction hashes stored are those of the platform's **own** daily-seal transactions
  (`seal_days.tx_hash`, sent from the platform's sealing account) — never a transaction of a
  visitor or a tenant. This is the wording of the "what we never store" card (plan D-4).
- Wallet-extension message traffic (Tier 2 not shipped); the Wallets Kit's localStorage keys; lists of installed wallets.
- From OpenTelemetry: client addresses, network peer addresses, user agents, full URLs and queries, request/response
  headers, request/response bodies, `enduser.*`, `user.*`, `session.id`, exception messages and stack traces, span events
  and links, exemplars, logs, host/process/container resource attributes. Payment amounts are never collected from OpenTelemetry
  either: the agent-payment events keep only a six-way order-of-magnitude bucket of a tenant server's own payment.
- Any cross-tenant visitor de-duplication or "reach" figure.
